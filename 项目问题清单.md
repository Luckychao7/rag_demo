### 2. FAISS 向量库文件名中文乱码

| 项目    | 内容                                                                                                                   |
| ----- | -------------------------------------------------------------------------------------------------------------------- |
| 严重程度  | 高                                                                                                                    |
| 根因    | FAISS 是 C++ 库，`faiss.write_index()` / `faiss.read_index()` 走 C 标准库 `fopen`，不支持中文文件路径。文档名「李凯朝简历」做文件名时编码崩坏，读写不匹配，搜索返回空 |
| 修复方案  | FAISS 文件名改用 `hashlib.md5(doc_id.encode("utf-8")).hexdigest()`（纯 ASCII），meta JSON 文件名保持原样（Python 原生支持中文）              |
| 涉及文件  | `vector_store.py`                                                                                                    |
| 涉及知识点 | C++ 库字符编码限制、MD5 哈希映射、UTF-8 vs GBK 编码差异                                                                               |

### 4. Streamlit 启动慢（14 秒）

### 5. LLM 暴露推理过程

| 项目    | 内容                                                                                                            |
| ----- | ------------------------------------------------------------------------------------------------------------- |
| 严重程度  | 高                                                                                                             |
| 根因    | `SYSTEM_PROMPT` 和 `RAG_PROMPT_TEMPLATE` 没有明确禁止 LLM 展示思考过程。qwen2:7b 是 7B 小模型，不禁止就会自言自语（如"这个问题是在询问文档中提到的个人的名字"） |
| 修复方案  | `SYSTEM_PROMPT` 加规则 6"直接给出答案，不要描述你的思考过程"；`RAG_PROMPT_TEMPLATE` 加规则 5 同样内容，双重保险                                |
| 涉及文件  | `rag_engine.py`                                                                                               |
| 涉及知识点 | 提示词工程、小模型行为控制                                                                                                 |

### 6. 非文档问题处理不一致

| 项目    | 内容                                                                                                             |
| ----- | -------------------------------------------------------------------------------------------------------------- |
| 严重程度  | 高                                                                                                              |
| 根因    | `SYSTEM_PROMPT` 说"只能根据文档回答"，但对天气、时间等常识问题，qwen2:7b 会用训练数据编造（如编出 22°C/65% 湿度等假数据），而对时间问题又正确拒绝了                   |
| 修复方案  | `SYSTEM_PROMPT` 加规则 7"如果问题与文档内容无关（如天气、时间、新闻、闲聊），直接说'这个问题超出文档范围，我无法回答'，不要编造信息"；`RAG_PROMPT_TEMPLATE` 加规则 6 同样内容 |
| 涉及文件  | `rag_engine.py`                                                                                                |
| 涉及知识点 | LLM 幻觉抑制、提示词工程                                                                                                 |

### 7. 多轮代词指代丢失（核心问题）

| 项目    | 内容                                                                                                                                                                            |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 严重程度  | 高                                                                                                                                                                             |
| 根因    | 用户多轮对话中用代词（如"他的教育背景是什么"），系统直接拿原始问题做 embedding 检索，"他"是高频通用词，与简历文本相似度极低，检索结果全是低分噪声，LLM 无法生成正确答案。旧代码 `assess_question()` 虽然传了 `chat_history` 给 LLM 做判断，但 `refined_query` 始终是原始问题 |
| 修复方案  | 重写 `assess_question()` 为查询重写 + 清晰度判断一体化函数。用 `ANALYZE_PROMPT` 指导 LLM 做代词消解 + 上下文补全，输出改写后的自包含检索查询。取最近 6 条历史消息构建上下文                                                              |
| 涉及文件  | `rag_engine.py`                                                                                                                                                               |
| 涉及知识点 | Query Rewriting、代词消解、多轮对话上下文管理、Embedding 检索质量优化                                                                                                                               |
| 面试话术  | "在检索前加一步 LLM query rewriting，把'他的教育背景'改写成'李凯朝的教育背景'，再去做 embedding 检索。LangChain 的 `create_history_aware_retriever` 用的也是同样思路"                                                   |

### 8. app.py 绕过 refined\_query（调用链断裂）

| 项目    | 内容                                                                                                                                                                |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 严重程度  | 高                                                                                                                                                                 |
| 根因    | `app.py` 的 `_handle_user_input()` 没调用 `full_qa_flow()`，自己重写了流程。`assess_question()` 返回的 `refined_query` 被丢弃，`_do_rag(prompt)` 始终传原始问题做检索。即使加了 query rewriting 也用不上 |
| 修复方案  | `_do_rag()` 新增 `search_query` 参数，`_handle_user_input()` 改为 `_do_rag(prompt, search_query=assessment["refined_query"])`。检索用改写后的查询，生成用原始问题，两者解耦                     |
| 涉及文件  | `app.py`                                                                                                                                                          |
| 涉及知识点 | 接口设计、调用链一致性、检索查询 vs 生成查询的解耦                                                                                                                                       |

### 9. 对话历史包含当前用户消息（重复）

| 项目    | 内容                                                                                                                                                                              |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 严重程度  | 中                                                                                                                                                                               |

### 10. Ollama 未设置 num\_ctx（上下文静默截断）

| 项目    | 内容                                                                                                                                                                                      |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 严重程度  | 高                                                                                                                                                                                       |
| 根因    | `llm_service.py` 的 Ollama payload 只有 `temperature`，没设 `num_ctx`。Ollama 默认上下文窗口 2048 tokens，RAG prompt（系统提示 + 6 条历史 + 5 个文本块）经常超过 2048，超了的部分被 **静默截断**。可能是答案矛盾的直接原因之一——系统提示被截断后，LLM 忘了规则 |
| 修复方案  | `config.py` 加 `OLLAMA_NUM_CTX = 8192`，`llm_service.py` payload 加 `"num_ctx": config.OLLAMA_NUM_CTX`                                                                                     |
| 涉及文件  | `config.py`、`llm_service.py`                                                                                                                                                            |
| 涉及知识点 | Ollama API 参数、上下文窗口管理、静默截断问题                                                                                                                                                            |

### 11. "不选=全部"文档搜索失效

### 12. Token 监控跨会话不隔离

| 项目    | 内容                                                                                                                                                                     |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 严重程度  | 中                                                                                                                                                                      |
| 根因    | token 信息存在 Python 全局变量 `_last_request_info` 中，跨 Streamlit 会话不隔离。浏览器刷新 → 新建 session → 全局变量还存着旧数据 → 显示旧对话的 token。切换对话/新建对话时清零无效，因为页面重新渲染时 `_check_ollama()` 又读到旧全局数据写回去了 |
| 修复方案  | token 信息改存到 `st.session_state.last_token_info`。每次 LLM 调用后写入 session state，新建/切换对话时清零。侧边栏和顶部 caption 都从 session state 读                                                 |
| 涉及文件  | `app.py`、`llm_service.py`                                                                                                                                              |
| 涉及知识点 | Streamlit session state 隔离、Python 全局变量生命周期、跨会话状态管理                                                                                                                     |

| 项目   | 内容                                                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------ |
